# Batch 17 plan (2026-10-07, register before running) - a mechanism-based filter

Mechanism (Batch 16, exact for C0, C10, C11): candidate (a1, b1) = partner (a2, b2) shifted by s = 1 and wrapped by one linear
factor lambda of b1, with a polynomial gauge U(n). Determinants force b2(n - s) = kappa x (product of TWO linear factors of
b1(n)) (checked: C0 b2(n-1) = (3n+2)(5n-4), C10 b2(n-1) = (2n-1)(3n-1), both pairs of factors of b1).
So the partner's b is fixed by a choice of factor pair; only a2 = alpha n + beta and kappa are free -> a very cheap search
over a much wider range than brute force.

## 17A (local) the 10 remaining candidates
For each candidate, each pair of linear factors of b1 (6 pairs), s in {-2, ..., 2}: b2(n) = kappa x pair(n + s),
kappa in +-{1, 2, 3, 4, 6, 8, 9, 12, 16, 18, 24, 36}; a2(n) = alpha n + beta, 1 <= alpha <= 12, |beta| <= 300.
Evaluate y (float, depth 600), hash against Mobius images (|coef| <= 8) of the candidate's x; matches re-checked at 160 digits
and then sent to the Batch-16 coboundary prover. Controls: C0, C7, C10, C11, C14 run through the same filter must recover
their known partners (or equivalent ones); 15 random reals as targets -> 0 verified matches.
Success: >= 1 verified match (160 digits) for one of the 10.
