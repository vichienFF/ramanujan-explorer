# Batch 5 plan (2026-10-06, register before running)

Lessons from Batch 4 (dd7a724):
(a) K2 zeta(5) produced no data: no per-trajectory timeout, blocks of 100 written only at block end.
(b) ramanujantools CMF.delta() without an explicit limit estimates the limit at the same depth, which can give
    delta = +inf artificially (e.g. slowly converging trajectories). K1's 66,077 "inf" trajectories are therefore unclassified.
(c) Catalan has a second hypergeometric representation without pi: 3F2(1/2, 1, 1; 3/2, 3/2; 1) = 2G (checked: PSLQ [0,-1,2,0]).
Fixes used in all jobs below: explicit limit computed first at depth 1500 (L), then delta at depths 200 and 400 against L;
per-trajectory timeout 60 s (signal.alarm); checkpoint every 10 trajectories.

## J1 (Kaggle, 2 kernels) zeta(5) via the 6F5 CMF - rerun of Batch 4 K2 with the fixes
Same CMF, start, trajectory set (20,000 seeded + 16 uniform) and success criterion as Batch 4 K2.

## J2 (Kaggle, 2 kernels) Catalan via two 3F2 CMFs, with explicit limits
CMF-A: pFq(3,2,-1) start (1/2,1/2,1;3/2,3/2) (as Batch 4 K1). CMF-B: pFq(3,2,1) start (1/2,1,1;3/2,3/2) (value 2G).
Trajectories: all primitive v in [-3,3]^5 for each CMF (about 2 x 16,000).
Each limit L is classified at 100 digits: rational / Mobius(G) / Mobius(pi) / G&pi combination / unidentified.
Primary success: a trajectory with delta_200 > 0 AND delta_400 > 0 whose limit is Mobius(G) or a G&pi combination with
nonzero G part. Always reported: best delta per class, counts. Control: zeta(3) CMF (1,1) delta ~ 0.084.
